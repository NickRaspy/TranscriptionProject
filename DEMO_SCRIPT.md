# План показа: до 5 минут

## 0:00–0:30 — задача

Коротко обозначить задачу: из четырёх B2B-разговоров получить итоги, согласованные действия, сроки, потребности, риски и вопросы руководителю. Результат должен опираться на реплики, без добавленных фактов.

## 0:30–1:15 — запуск

Из корня проекта выполнить `.\run-demo.cmd`. Показать `Validated 4 transcript(s)`, затем открыть `results.json` и `report.html`. Сказать прямо: demo использует вручную проверенный файл `data/demo-results.json`; обращения к модели в этом запуске нет.

## 1:15–3:15 — отчёт

Открыть `report.html`:

1. «Альфа-Металл»: КП преждевременно; Анна сегодня отправляет приглашение и вопросы, техническая встреча 10 сентября в 15:00 по Екатеринбургу. Пилот — лишь при подтверждении реализуемости.
2. «Зелёная Полка»: список данных к 9 сентября; расчёт и план к 14 сентября. Сумма 160 000 рублей — желаемый потолок, а 120 000 рублей — неполное по составу предложение конкурента.
3. «СтройКомплект»: замена CRM отвергнута; сначала NDA, затем обезличенные записи. Звонок 11 сентября в 11:30; часовой пояс не назван.
4. «Север-Транс»: покупка сейчас отклонена по времени; материал в декабре и контакт после 20 января. Точного дня для обоих действий нет.

Для каждого разговора открыть хотя бы одну цитату, на которой основан вывод.

## 3:15–4:15 — проверка и устройство

После `build.cmd -c Release` выполнить `.\test.cmd`. Показать 22 NUnit-теста. Среди них проверки обязательных полей, дат, цитат, HTML, аргументов запуска и обмена с API через подставной HTTP-обработчик. В режиме API ответ модели проходит тот же валидатор.

## 4:15–4:45 — ограничения

Указать границу проверки: живого вызова API не было, поскольку ключ в среде не задан. Валидатор проверяет форму ответа и наличие цитат в транскрипте. Смысловую точность выводов нужно оценивать отдельно на новых разговорах.
