# MVP анализа B2B-транскриптов

Консольное приложение .NET 8 анализирует текстовые транскрипты и записывает `results.json` и `report.html`. В репозитории лежат четыре разговора из задания и результаты для показа без API.

## Быстрый запуск

На Windows из корня проекта:

```powershell
.\run-demo.cmd
```

Команда сверяет SHA-256 входных файлов с четырьмя исходными разговорами, читает вручную проверенный `data/demo-results.json`, проверяет поля и цитаты, затем создаёт оба выходных файла. После записи приложение снова читает `results.json` и запускает ту же проверку. В режиме `--demo` запросов к модели нет.

Обычный запуск в окружении с доступным NuGet:

```powershell
dotnet build
dotnet test -c Release
dotnet run --project src -- --demo
```

Если локальные настройки NuGet мешают сборке, на Windows запустите `.\build.cmd -c Release`, затем `.\test.cmd`. Скрипты размещают служебные файлы .NET в папке проекта; `NuGet.Config` указывает источник nuget.org. Для первой сборки тестов понадобится доступ к NuGet: тестовый проект использует NUnit, NUnit3TestAdapter и Microsoft.NET.Test.Sdk. Само приложение обходится без внешних пакетов. `test.cmd` работает с уже восстановленными пакетами.

## Запуск с Gemini

Получите ключ в [Google AI Studio](https://ai.google.dev/gemini-api/docs/api-key). В корне проекта создайте `.env` со строкой `GEMINI_API_KEY=ваш_ключ` (без кавычек). В этой рабочей папке файл уже создан, осталось вписать ключ. Затем запустите:

```powershell
.\run-gemini.cmd
```

Скрипт отправляет все четыре транскрипта в Gemini API и сохраняет результат в `gemini-output/results.json` и `gemini-output/report.html`. Это живой вызов модели, в отличие от `--demo`. По умолчанию используется `gemini-3.5-flash`; модель можно заменить через переменную среды `GEMINI_MODEL`. Файл `.env` исключён из Git, а ключ не записывается в результаты. Папка `gemini-output/` тоже исключена из Git, чтобы непроверенный ответ модели не попал в публикацию случайно.

## Запуск с OpenAI или совместимым API

Установите `OPENAI_API_KEY` в окружении и запустите:

```powershell
dotnet run --project src -- --input data/transcripts --output .
```

Можно задать `OPENAI_BASE_URL` (по умолчанию `https://api.openai.com/v1`) и `OPENAI_MODEL` (по умолчанию `gpt-4o-mini`). Для каждого файла приложение отправляет запрос в `chat/completions` с `response_format: json_object`, разбирает ответ и проверяет его тем же валидатором, что и demo-данные. Ключ берётся из окружения и не записывается в результат. OpenAI API оплачивается отдельно от подписки ChatGPT; `--demo` баланс API не расходует.

`--input` принимает файл `.txt` или папку с файлами `.txt`. ID берётся из имени файла без расширения. `--output` задаёт папку для результатов. Новые транскрипты обрабатываются только в режиме API; demo принимает четыре исходных файла с известными SHA-256. Неизвестные и повторные аргументы командной строки вызывают ошибку.

## Структура и подход

- `src/Program.cs`: загрузка файлов, проверка demo-материалов и запись результата.
- `src/CommandLineOptions.cs`: разбор аргументов и проверка ошибок ввода.
- `src/OpenAiAnalyzer.cs`: запрос к API и разбор ответа.
- `src/GeminiAnalyzer.cs`: запрос к Gemini API и разбор JSON-ответа.
- `src/AnalysisPrompt.cs`: общие инструкции и контекст для обеих моделей.
- `src/Models.cs`: типизированная схема разговора, шага и подтверждающей цитаты.
- `src/ResultValidator.cs`: обязательные поля и массивы, ISO 8601, запрет точной даты при неоднозначном сроке, проверка цитат по исходному тексту.
- `src/ReportBuilder.cs`: HTML с экранированием пользовательского текста.
- `tests/ResultTests.cs`: проверки результатов кейса, дат, цитат и экранирования HTML.
- `tests/IntegrationTests.cs`: аргументы запуска и запросы к обоим API через подставной HTTP-обработчик. Сеть в тестах не используется.
- `data/transcripts/`: четыре исходных разговора; `data/demo-results.json`: вручную составленные и проверенные ответы.

`nextStep` содержит ближайшее согласованное действие. Более поздние действия сохраняются в `additionalAgreedActions`. Условные перспективы, например пилот после подтверждения технической возможности, описаны как условия и не выданы за безусловное обязательство. Для встречи 10 сентября указан часовой пояс Екатеринбурга `+05:00`. Для звонка 11 сентября часовой пояс в исходнике не назван, поэтому время сохранено без смещения. Для декабря и «после двадцатого января» точная дата оставлена `null`.

## Проверка результата

Сборка Release проходит без предупреждений. Набор из 26 NUnit-тестов проверяет данные четырёх разговоров, даты, обязательные поля (включая `missingOrAmbiguousInformation`), цитаты в `evidence`, HTML, аргументы запуска и формат запросов к OpenAI и Gemini. `run-demo.cmd` создаёт `results.json` и `report.html`; записанный JSON повторно читается и проверяется.

Итоги и действия сверены вручную с репликами. Проверены даты: «сегодня» 8 сентября, четверг 10 сентября, «завтра» 9 сентября, понедельник 14 сентября и пятница 11 сентября. Для декабря и срока после 20 января точный день не указан.

## Где решение может ошибаться

Gemini API проверен на всех четырёх разговорах с моделью `gemini-3.5-flash`: ответы записаны после проверки структуры, дат и цитат. В третьем разговоре модель пропустила условную передачу десяти обезличенных записей после согласования NDA, хотя она есть в исходнике и проверенном demo-ответе. Валидатор не выявляет такие пропуски и не доказывает правильность выводов; результат нужно сверять с репликами вручную. OpenAI API в этой среде не запускался; подставной HTTP-обработчик проверяет только запрос и разбор ответа. У совместимых с OpenAI API может отличаться поддержка `response_format: json_object`. При временной ошибке Gemini API запуск можно повторить; автоматического повтора HTTP-запроса нет.

## Следующая итерация

Проверить API-режим на новых транскриптах и вручную оценить каждый вывод по исходным репликам. Затем добавить проверку дат и связи выводов с цитатами, обработку временных ошибок API и возможность исправить результат перед сохранением. Загрузка PDF и аудио пока не реализована.
